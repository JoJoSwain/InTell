# Brief: M1, audio engine spike

**Milestone:** M1 (BUILD_PLAN), the highest technical risk; it must be settled before any other audio work
**Branch:** `m1-audio-spike`, from `origin/master` **after M0 is merged**
**Author:** architect (Claude), 2026-11-19
**Read first:** `AGENTS.md`, `apps/mobile/AGENTS.md`, `docs/AUDIO_SPEC.md` §2 and §6, `docs/BUILD_PLAN.md` M1, `docs/TECH_SPEC.md` §1 (Audio row)

## Goal
Prove, on real phones, whether `react-native-audio-api` can run InTell's whole mix (narration, 3 synced music stems, a crossfading ambience bed, random one-shots, bus ducking) for **60 minutes with the screen locked**, with lock-screen controls, route detection and interruption handling. Record the result in **ADR 0001**. Everything about the three sound layers depends on this answer.

The work has three phases:
1. **Cursor:** build the `AudioEngine` interface, the implementation, a hidden test screen, generated test audio and logging.
2. **JoJo:** run the device test protocol (Appendix A) and record the results.
3. **Cursor:** write ADR 0001 from the recorded results.

## Part A: the shared interface (`packages/shared/src/audio/AudioEngine.ts`)
Types only, exported from `packages/shared/src/index.ts`. Follow AUDIO_SPEC §2.2, made concrete:

```ts
export type BusId = 'story' | 'music' | 'surroundings' | 'ui';
export type AudioRoute = 'headphones' | 'bluetooth' | 'speaker' | 'unknown';

export interface BufferHandle { readonly sha: string; readonly durationMs: number; }
export interface VoiceHandle { readonly id: string; }
export interface LoopGroupHandle { readonly id: string; readonly stemCount: number; }

export interface NowPlayingMeta { title: string; artist: string; artworkUri?: string; }

export interface EngineDiagnostics {
  uptimeMs: number;
  activeVoices: number;
  loopGroups: { id: string; stemPositionsMs: number[]; maxStemDriftMs: number }[];
  narrationPositionMs?: number;
  underruns?: number;            // if the library exposes it
  route: AudioRoute;
}

export interface AudioEngine {
  init(opts: { mixWithOthers: false }): Promise<void>;
  load(sha: string, uri: string): Promise<BufferHandle>;           // decoded + LRU cached by sha (64 MB cap)
  playNarration(h: BufferHandle, meta: NowPlayingMeta, startAtMs?: number): VoiceHandle;
  pauseNarration(): void;
  resumeNarration(): void;
  playOneShot(h: BufferHandle, p: { bus: BusId; gainDb: number; pan: number; rate: number }): VoiceHandle;
  startLoopGroup(bus: BusId, stems: { h: BufferHandle; gainDb: number; loopStartMs: number; loopEndMs: number }[]): LoopGroupHandle;
  crossfadeBed(bus: BusId, from: VoiceHandle | null, to: BufferHandle, p: { gainDb: number; fadeMs: number; loopStartMs: number; loopEndMs: number }): VoiceHandle;
  setGain(target: VoiceHandle | LoopGroupHandle | BusId, gainDb: number, rampMs: number): void;
  setStemGain(group: LoopGroupHandle, index: number, gainDb: number, rampMs: number): void;
  stop(target: VoiceHandle | LoopGroupHandle, fadeMs: number): void;
  onRouteChange(cb: (route: AudioRoute) => void): () => void;
  onInterruption(cb: (e: 'began' | 'ended') => void): () => void;
  onNarrationProgress(cb: (p: { positionMs: number; durationMs: number }) => void): () => void;
  onRemoteCommand(cb: (c: 'play' | 'pause' | 'skipForward' | 'skipBackward' | 'next') => void): () => void;
  getDiagnostics(): EngineDiagnostics;
  dispose(): Promise<void>;
}
```
Also add pure helpers with Vitest tests: `dbToGain(db)`, `gainToDb(g)`, `equalPowerCrossfade(t)` returning `{ fromGain, toGain }`, and a `DuckingPolicy` matching AUDIO_SPEC §2.3 (bus defaults, duck amounts, 800 ms attack / 2500 ms release, and the extra -6 dB on speaker for surroundings). Small, fully tested.

## Part C: generated test audio
`tools/audio-fixtures/` contains a small Node or TypeScript script, with no new dependencies beyond what's in the repo, that writes 44.1 kHz WAV (convert to AAC only if the library requires it, using a dependency-free path or reporting the need):

| File | Content | Why |
|---|---|---|
| `narration_3min.wav` | Mono; a 300 Hz tone with a spoken-rhythm amplitude envelope; a short 1 kHz beep every 10 s | Ducking and progress are audible |
| `stem_a.wav`, `stem_b.wav`, `stem_c.wav` | Stereo, exactly 32.000 s each, 120 BPM; each has a sharp click on **every beat at the same sample offset**, plus a different sustained pitch (A2, E3, A3) | **Drift test:** if stems drift, the clicks "flam" (doubled clicks you can hear) |
| `bed_wind.wav`, `bed_water.wav` | Stereo filtered noise, 60 s, seamless loop | Crossfade test |
| `oneshot_1..6.wav` | 0.3–2 s chirps and taps | Random one-shot scheduling |

Write the outputs to `apps/mobile/assets/spike-audio/`. Keep the total under 25 MB, and add a README there saying they are synthetic test fixtures.

## Appendix A: device test protocol (for JoJo)
Copy this to `docs/spikes/M1-audio-test-results.md` as a results template.

**Setup:** charge the phone above 80%, close other apps, set the volume to 50%, and turn on Do Not Disturb (except calls, for T5). Open `intell://dev/audio-spike` and tap **Start full mix**.

| # | Test | How | Pass if |
|---|---|---|---|
| T1 | 60-minute locked run | Lock the screen. Keep the phone in a pocket or on a table for 60 minutes with headphones on; listen at minutes 0, 15, 30, 45 and 60 | No dropouts or stutters; audio still playing at 60 minutes |
| T2 | Stem alignment | During T1, listen for doubled clicks; afterwards check `maxStemDriftMs` in the log | No flams; logged drift ≤ 5 ms throughout |
| T3 | Ducking | Toggle narration several times | Music and surroundings dip and recover smoothly; no clicks or pops |
| T4 | Route switching | Unplug wired headphones, connect and disconnect Bluetooth, switch to speaker | Every switch is logged; playback continues (or pauses on unplug, per the spec) |
| T5 | Phone call | Have someone call you mid-mix; answer, then hang up | Audio pauses for the call and resumes (or can be resumed) after it |
| T6 | Other app audio | Play a song in another app, then return | An interruption is logged; the spike resumes cleanly |
| T7 | Lock-screen controls | Use play/pause on the lock screen and headphone buttons | The commands work; metadata shows "InTell audio spike" |
| T8 | Memory | Android: `adb shell dumpsys meminfo org.replaceplace.intell` at minutes 5, 30 and 60. iOS: Xcode Instruments (or the EAS dev-client memory display) if available | Total PSS / memory footprint < 150 MB, with no steady climb |
| T9 | Battery (informational) | Note the battery % at the start and at 60 minutes | Record it; the target for M7 is < 12% for the full product |

Record for each test: pass or fail, the device and OS version, and notes. Attach `audio-spike-log.jsonl`.
